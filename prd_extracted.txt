This document provides a comprehensive breakdown of all modules, API groups, database schema, workflows, and feature roadmap for the LunexAK platform. It serves as the primary development reference for the engineering team.

SECTION 1 — PLATFORM OVERVIEW

LunexAK is a premium brand-led D2C e-commerce platform built for lifestyle and consumer products. The system combines a polished storefront experience with controlled internal workflows — including role-based access, admin-gated product publishing, automated order communications, and a scalable MongoDB-backed architecture.

Core Objectives
▸  Premium consumer browsing experience
▸  Login-required checkout flow
▸  Admin-controlled product approval
▸  Employee-assisted product entry
▸  SEO-first architecture
▸  Automated order email system
▸  Scalable D2C foundation

Technology Stack
▸  Frontend: React / Next.js (SSR)
▸  Backend: Node.js + Express (REST API)
▸  Database: MongoDB (Mongoose ODM)
▸  Auth: JWT + Refresh Tokens
▸  Media: CDN / Object Storage
▸  Email: Transactional Email Service
▸  Search: Full-text + Filter Engine

SECTION 6 — KEY WORKFLOWS

6.1  Product Creation & Approval Workflow

1
Employee logs in and opens the Employee Panel → New Product form
2
Employee fills all required fields: title, description, price, category, variants, stock, and SEO data
3
Employee uploads product images with alt text and sets sort order
4
Employee saves product as a Draft (auto-saved) or clicks Submit for Review
5
System sets product status to PENDING — product is not visible on the storefront
6
Admin receives notification in dashboard: new product awaiting approval
7
Admin opens the product review screen and inspects all content, images, pricing, and SEO
8
Admin APPROVES → product status changes to APPROVED; Admin can publish immediately or schedule
8
Admin REJECTS → product status returns to REJECTED with admin comment; employee is notified
9
Employee corrects the rejected product and resubmits — the cycle repeats from Step 4
10
Approved product is PUBLISHED → appears on the public storefront with full SEO indexing

6.2  Customer Order Workflow

1
Customer (or visitor) browses the storefront — no login required for browsing
2
Customer adds product(s) to cart — cart is persisted in the database for logged-in users
3
Customer clicks Checkout — system checks authentication status
4
If not logged in → redirected to Login / Register page, then returned to checkout after authentication
5
Customer selects a saved address or enters a new delivery address
6
Order summary page displays: items, quantities, pricing breakdown, delivery address
7
Customer confirms and places the order
8
System: creates order record, locks in pricing snapshot, deducts stock, clears cart
9
System: triggers order confirmation email to customer with full order details
10
Admin dashboard reflects new order — team processes fulfillment
11
Admin updates order status: Confirmed → Dispatched → Delivered (each step triggers email)

6.3  User Registration & Login Workflow

1
User opens Registration form — enters name, email, and password
2
System validates input, hashes password, creates user record with isVerified: false
3
System sends email verification link to the provided email address
4
User clicks link → system marks isVerified: true and activates the account
5
User logs in with email and password — system validates credentials
6
System issues Access Token (short-lived) and Refresh Token (long-lived, HttpOnly cookie)
7
Access Token is used for all authenticated API requests in the session
8
On token expiry → client uses Refresh Token to silently obtain a new Access Token
9
Logout → system invalidates Refresh Token; user must re-authenticate

6.4  Email Notification Workflow

1
Triggering event occurs: order placed, status updated, cancellation, etc.
2
Backend Notification Service receives the event with user ID and order ID
3
Service fetches customer data, order data, and selects the correct email template
4
Email is compiled: brand logo, order number, customer name, items, address, support info
5
Email is sent via Transactional Email Provider (SendGrid / Mailgun / SES)
6
Notification record is created in the notifications collection (emailSent: true)
7
In-app notification is also created for the customer's account notification center
8
Failed sends are queued for retry — admin can view email logs in the dashboard

▸  Structured subheadings (H2, H3)

SECTION 8 — SECURITY & PERFORMANCE

8.1  Security

Authentication Security
▸  bcrypt password hashing (min cost factor 10)
▸  JWT access tokens (15-min expiry)
▸  Refresh tokens in HttpOnly, Secure cookies
▸  Email verification before account activation
▸  Secure password reset via time-limited link
▸  Role claim embedded in token payload

API & Request Security
▸  Role-based middleware on all protected routes
▸  Input validation and sanitization (express-validator)
▸  Rate limiting on auth and sensitive endpoints
▸  File upload validation: type, size, count limits
▸  CSRF protection on state-changing requests
▸  Audit logging for all critical admin actions
▸  Customers access only their own data

8.2  Performance

Frontend Performance
▸  Next.js SSR / SSG for fast initial load
▸  Image optimization via Next/Image or CDN
▸  Lazy loading of images and off-screen content
▸  Code splitting per route
▸  Loading skeleton states for async content
▸  Minimal unnecessary re-renders (memoization)

Backend Performance
▸  MongoDB indexes on: slug, categoryId, status, tags, userId
▸  Category data cached (Redis or in-memory)
▸  Pagination on all list endpoints
▸  Object storage / CDN for all media assets
▸  Database query projection (return only needed fields)
▸  Search indexing for fast full-text retrieval
